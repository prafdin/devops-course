# Дизайн: сайт-обёртка на Hugo с навигацией по темам между годами

## Контекст

Сейчас публикуемый на GitHub Pages сайт — это голый HTML, генерируемый
bash-heredoc'ами в `Makefile` (корневом и в каждом `YYYY/Makefile`):
моноширинный шрифт, фиксированная ширина 40em, без viewport meta,
списки ссылок на PDF без какой-либо связи между годами. Логика
генерации дублируется между корневым Makefile и погодовыми.

Материалы (слайды Beamer, методички) остаются в LaTeX и продолжают
собираться в PDF существующим пайплайном (`makefile.defs`,
`latexmk-action` в CI) — это вне скоупа. Меняется только то, как
собранные PDF представлены на сайте.

Проблема, которую решает этот дизайн: темы курса физически лежат в
разных, несогласованно пронумерованных папках по годам (например,
`2025/06-docker` и `2026/07-docker-intro` + `2026/08-docker-commands`),
и сейчас нет способа увидеть все годовые версии одной темы рядом.

## Архитектура

Новая директория `site/` — самостоятельный Hugo-проект, не
затрагивающий LaTeX-исходники в `2025/`/`2026/`:

```
site/
  hugo.toml
  content/
    2025/
      _index.md            — годовая страница (others и т.п.)
      01-what-is-devops/_index.md
      02-proxy/_index.md
      ...
      assignments/01-git-webhooks/_index.md
      ...
      others/01-course-questions/_index.md
    2026/
      _index.md
      01-what-is-devops/_index.md
      ...
      assignments/01-git-webhooks/_index.md
      ...
      extra/exam/_index.md
  layouts/
    index.html          — главная: список тем
    topics/topics.html  — страница одной темы: все годы рядом
    _default/year.html  — годовая страница (для content/<year>/_index.md)
    partials/head.html, header.html, footer.html
  static/                  — сюда в CI копируются собранные PDF
```

Контент-структура в `content/` зеркалит существующие папки `2025/` и
`2026/` (простая синхронизация: новая лекция — новая папка), а связь
между темами разных лет обеспечивает **taxonomy `topics`** во front
matter, а не совпадение путей/номеров.

## Front matter и модель данных

Каждая лекция/задание — headless page bundle (не рендерится как
отдельная страница, служит только источником данных для taxonomy):

```yaml
---
title: "Docker: введение"
topics: ["docker"]
kind: "lecture"      # lecture | assignment | extra
year: 2026
pdf: "/2026/07-docker-intro/07-docker-intro.pdf"   # путь относительно site root после сборки
video: "https://disk.yandex.ru/i/eOyzlNKjqpFEaw"   # опционально
weight: 7
_build:
  render: false
  list: always
---
```

`pdf` — полный путь от корня сайта, без магии вывода из имени
файла/папки: меньше связности между шаблоном и структурой файлов,
проще проверять скриптом (см. «Валидация»).

`topics` — список из одного или нескольких slug'ов; год не входит в
slug (`docker`, не `docker-2026`), именно это даёт кросс-годовую
группировку бесплатно, силами Hugo taxonomy.

`kind` разделяет лекции/задания/прочее (`extra`) на странице темы и на
годовых обзорных страницах экзаменационных материалов, которые не
привязаны к отдельной теме.

## Data flow (сборка)

1. `2025/Makefile`, `2026/Makefile` (без изменений в части `pdfs`):
   LaTeX → PDF на месте, рядом с `.tex`.
2. Новый шаг (замена нынешней генерации `package/index.html`):
   скрипт копирует все `*.pdf` из `2025/` и `2026/` в
   `site/static/<year>/<topic-dir>/...`, сохраняя относительный путь.
   Название по аналогии с существующим `collect-deps.sh` —
   `collect-pdfs.sh`.
3. `hugo build` в `site/` → `site/public/`.
4. CI (`.github/workflows/latexmk.yml`): после шага `latexmk-action`
   добавляются шаги установки Hugo, запуска `collect-pdfs.sh` и
   `hugo build`; `JamesIves/github-pages-deploy-action` деплоит
   `site/public` вместо `package`.
5. Корневой `Makefile`: `package/index.html`-таргет (генерация
   верхнеуровневого списка годов) удаляется; `years-all` остаётся
   (компиляция PDF), добавляется таргет, дергающий `collect-pdfs.sh` +
   `hugo build` для локальной сборки (`make all` = PDF + сайт).
   Погодовые `Makefile` теряют свои `package/index.html`-таргеты
   аналогично, `pdfs` не трогаем.

## Шаблоны

- `layouts/index.html` — сортированный список тем
  (`site.Taxonomies.topics`) со счётчиком материалов, ссылка на
  `/topics/<slug>/`.
- `layouts/topics/topics.html` — страница темы: `.Pages`,
  сгруппированные по `.Params.year` (убывание), внутри года —
  отдельно `kind: lecture` и `kind: assignment`, каждая строка —
  заголовок + ссылка на PDF (+ ссылка на видео, если есть).
- Общий `partials/head.html` с `viewport` meta и адаптивной CSS без
  фреймворков и JS-зависимостей — соответствует духу текущего сайта
  (простой статический HTML), но с адаптивной вёрсткой вместо
  фиксированной ширины 40em.
- Годовые страницы с `others`/`extra` (вопросы к экзамену и т.п.,
  не привязанные к теме) — отдельная простая страница на год
  (`layouts/_default/year.html` для `content/<year>/_index.md`),
  вне taxonomy.

## Валидация

Скрипт `site/check.sh`, запускаемый в CI перед деплоем (после
`hugo build`, до deploy-action):

- Для каждого `pdf:` из front matter — проверка, что файл существует в
  `site/static<pdf>` (ловит опечатку в пути или забытый
  `collect-pdfs.sh`).
- Список используемых `topics` сверяется с `site/data/topics.yaml`
  (плоский список канонических slug'ов с человекочитаемым названием
  для заголовка страницы темы) — ловит опечатку/дубликат вида
  `docker` vs `dockers`.

Ошибка любой из проверок — build fails, ничего не деплоится с
неисправным контентом (аналог «fail fast» уже применяемого в CI
latexmk-пайплайне).

## Тестирование / проверка на местах

- Локально: `hugo server` в `site/` после `collect-pdfs.sh` — живой
  просмотр, включая мобильную ширину (viewport в devtools).
- `check.sh` можно гонять локально так же, как в CI.
- Ручная проверка перед мерджем: открыть страницу темы, где есть и
  2025, и 2026 версии (например, `docker` или `cicd`), убедиться, что
  обе колонки на месте и PDF открываются.

## Вне скоупа

- Поиск по сайту, отдельные полноценные страницы под каждую
  лекцию/задание, конвертация LaTeX в HTML — сознательно не делаем
  (см. решение оставить PDF как источник контента).
- Ретроактивное исправление нумерации/имён папок в `2025/`/`2026/` —
  темы связываются только через `topics` во front matter, папки не
  переименовываются.
