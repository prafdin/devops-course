В данной работе мы изучим механизм GitHub webhooks — автоматических HTTP запросов, которые отправляются при определенных событиях в репозитории.
Как показано на схеме выше, процесс работы состоит из следующих этапов:
\begin{enumerate}
    \item \textbf{Событие в репозитории}: разработчик выполняет push, создает pull request или другое действие
    \item \textbf{Активация webhook}: GitHub автоматически отправляет HTTP POST-запрос на настроенный URL
    \item \textbf{Обработка через прокси}: реверс-прокси перенаправляет запрос к обработчику
    \item \textbf{Автоматическое развертывание}: обработчик получает HTTP запрос и запускает процесс сборки/развертывания приложения
    \item \textbf{Обратная связь}: обработчик может отправить статус выполнения обратно в GitHub
\end{enumerate}

Этот подход позволяет использовать Git-репозиторий не только как средство совместной работы с кодом, но и как центральный
элемент автоматизации процессов разработки и развертывания ПО, что является ключевой практикой DevOps.

\begin{task}{3}
    Настроить webhook в GitHub репозитории
    
    \begin{enumerate}
        \item Перейдите в Settings → Webhooks → Add webhook
        \item Укажите Payload URL: \texttt{http://webhook.\$ID.\$PROXY} (используйте свои значения из задания 2)
        \item Укажите Content type: \texttt{application/json}
        \item Выберите нужное события для активации webhook или укажите \texttt{Send me everything}
        \item Сохраните webhook
    \end{enumerate}

    Для отладки можете воспользоваться \href{https://docs.github.com/en/webhooks/testing-and-troubleshooting-webhooks/testing-webhooks#testing-webhook-code-locally}{инструкцией} по настройке проксирования вебхуков без использования FRP.
\end{task}

\begin{task}{4}
    Создать обработчик webhook и настроить автоматическое развертывание приложения.
    
    \begin{enumerate}
        \item Создайте веб-сервер — обработчик webhook, который будет получать HTTP запросы от GitHub
        \item В качестве обработки события реализуйте логику автоматического развертывания приложения при получении push события:
        \begin{itemize}
            \item Клонирование или обновление кода из репозитория
            \item Сборка приложения (если требуется)
            \item Запуск тестов
            \item Развертывание и перезапуск веб-сервера или приложения
        \end{itemize}
        \item Протестируйте работу webhook сервера, создав событие в репозитории
        \item Убедитесь, что приложение успешно разворачивается и доступно
        \item Отправьте статус развертывания в GitHub через \href{https://docs.github.com/en/rest/commits/statuses?apiVersion=2022-11-28#create-a-commit-status}{REST API}. Опционально
    \end{enumerate}

    \textbf{Примечание:}
    \begin{itemize}
        \item Все необходимые зависимости приложения предварительно могут быть установлены вручную на виртуальной машине.
        Список зависимостей должен быть зафиксирован в документации или специальном файле, например, в requirements.txt в случае Python приложения.
        \item Веб-сервер — обработчик должен быть запущен на порту 8080, а развертываемое приложение должно быть доступно по адресу \texttt{http://app.\$ID.\$PROXY} и запущено на порту 8181
        \item Автоматическое развертывание должно работать для любой ветки в репозитории
        \item Учтите, что основное приложение должно работать, даже если webhook сервер отключен.
        Для решения этой задачи настоятельно рекомендуется превратить приложение в systemd сервис (\href{https://webdock.io/en/docs/how-guides/app-installation-and-setup/how-daemonize-application-systemd}{инструкция 1}, \href{https://medium.com/@benmorel/creating-a-linux-service-with-systemd-611b5c8b91d6}{инструкция 2})
    \end{itemize}

\end{task}
