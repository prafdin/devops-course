        \begin{frame}{Кейс 1}
            Пятница. Вечер. В конце рабочего дня разработчик вручную выкатывает билд на прод. Через час пользователи жалуются
            на баги, а восстановить прошлую версию невозможно: она только на ноуте разработчика, который уже уехал.
            \begin{enumerate}
                \item Нужно заставить Васю лучше тестировать
                \item Надо было подождать до понедельника
                \item Не хватает процессов и автоматизации
                \item Баги — это нормально, в понедельник починим
            \end{enumerate}
        \end{frame}

        \begin{frame}{Кейс 2}
            Сисадмин Петя устанавливает новую версию приложения на прод. Предварительно разработчик Вася и тестировщик Саша тестировали
            эту версию на стейджинге. После релиза пользователи жалуются: приложение начало работать заметно медленее.
            Оказывается, дело в новом функционале.
            \begin{enumerate}
                \item Нужно лучше тестировать, а лучше нанять ещё 2 QA инженеров
                \item Автоматизировать настройку серверов
                \item Купить более мощные сервера для продакшена
                \item Вася должен писать больше тестов
            \end{enumerate}
        \end{frame}
    }

        \begin{frame}{Кейс 3}
            Разработчик Вася сделал новую фичу, которая увеличивает использование диска. Сисадмин Петя не знал про новую фичу.
            Через два дня приложение падает — место закончилось.
            \begin{enumerate}
                \item Ввести правило: все новые фичи должны согласовываться с Ops за 3 дня
                \item Закупить ``железо`` про запас
                \item Настроить мониторинг и квотирование
                \item Петя должен смотреть все ченжлоги перед релизом
            \end{enumerate}
        \end{frame}

        \begin{frame}{Кейс 5}
            Разработчик Вася за два дня сделал фичу, которая, предположительно, принесет много новых клиентов компании
            При этом ближайшее окно релиза через 3 недели.
            \begin{enumerate}
                \item Разрешить релизить важные фичи вне окна релиза
                \item Мобилизировать тестировщиков с других активностей
                \item Ввести ежедневыне планерки для пересмотра приоритетов
                \item Вообще убрать окна релиза и релизить по желанию
            \end{enumerate}

        \begin{frame}{Кейс 6}
            Неожиданно сайт перестает работать. Выяснилось, что кто-то удалил таблицу users в базе данных.
            Резервная копия устарела, логи не велись.
            \begin{enumerate}
                \item Разрешить работать с prod базой только ``роботам``
                \item Поменять все пароли и сообщить их только некоторым синьорам
                \item Вести список ``провинившихся`` разработчиков
                \item Нанять отдельного специалиста DBA
            \end{enumerate}
        \end{frame}

    %       Что следует сделать чтобы избежать такой проблемы в будущем?
        \begin{frame}{Кейс 7}
            Вася завершил выпуск новой функции приложения, но на следующий день ушёл в планируемый отпуск. Остальные сотрудники не знают, как её тестировать,
            настраивать и использовать, из-за отсутствия документации.
            \begin{enumerate}
                \item Внести в общие правила пункт ``Не уходить в отпуск без документации``
                \item Нанять отдельного техписателя для написания документации
                \item Ввести в KPI пункт ``покрытие документацией``
                \item Задача выполнена только тогда, когда она в prod и протестирована
            \end{enumerate}
        \end{frame}

    \begin{frame}{DevOps - это культура}
        \begin{itemize}
            \item Совместная ответственность Dev и Ops (+QA, Sec)
            \item Автоматизация сборки, тестирования и доставки
            \item Повторяемая инфраструктура как код
            \item Быстрая и надёжная обратная связь
            \item Прозрачность процессов
        \end{itemize}
    \end{frame}

    \begin{frame}{Ключевые практики DevOps}
        \begin{itemize}
            \item CI/CD
            \item Infrastructure as Code (IaC), \href{https://www.cloudbees.com/blog/what-is-everything-as-code-eac\#why-should-you-adopt-everything-as-code}{Everything as Code (EaC)}
            \item Monitoring, Observability
            \item Культура сотрудничества: shared responsibility, blameless postmortems
        \end{itemize}
    \end{frame}

    \begin{frame}{Заключение}
        \begin{itemize}
            \item DevOps — это культура, а не просто инструменты или практики.
            \item Решение системных проблем требует комплексного подхода.
            \item DevOps объединяет разработку, тестирование, эксплуатацию и безопасность.
            \item Внедрение DevOps — это постепенный процесс.
        \end{itemize}
    \end{frame}
