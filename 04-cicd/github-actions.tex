\section{Цель работы}

Сравнить подходы и изучить преимущества CI/CD платформ.

\section{Содержание работы}

В предыдущей работе был создан webhook обработчик, который автоматически разворачивал приложение при событии в репозитории.
GitHub Actions позволяет решить ту же задачу без написания собственного обработчика и с дополнительными возможностями.

\vspace{0.5cm}
\textbf{Основные компоненты GitHub Actions:}
\begin{itemize}
    \item \textbf{Workflow} — набор из одной или нескольких задач (Job) автоматизации
    \item \textbf{Job} — логическое объединение шагов (Step) автоматизации
    \item \textbf{Step} — непосредственно исполняемое действие автоматизации.
    Например, запуск shell скриптов или вызов готовых наборов задач — Action
    \item \textbf{Action} — заранее определенный набор задач (Job), предоставляемый GitHub или сообществом
    \item \textbf{Runner} — сервер, который выполняет workflows
\end{itemize}

\vspace{0.5cm}
\textbf{Преимущества GitHub Actions перед webhook веб-сервером:}
\begin{itemize}
    \item Встроенная интеграция с GitHub
    \item Широкий выбор готовых actions
    \item Визуальный интерфейс и логи
    \item Безопасное хранение секретов
    \item Не требует собственной инфраструктуры для \href{https://docs.github.com/en/billing/concepts/product-billing/github-actions?versionId=free-pro-team%40latest&productId=actions&restPage=get-started%2Cunderstand-github-actions#free-use-of-github-actions}{небольших проектов}
\end{itemize}

\begin{task}{1}
    Подготовить репозиторий из предыдущей лабораторной работы.
    
    \begin{enumerate}
        \item Создайте отдельную ветку для работы с GitHub Actions (например, \texttt{github-actions})
        \item Временно отключите webhook: в настройках репозитория (Settings → Webhooks) снимите галочку \texttt{Active} у конкретного webhook
        \item Создайте SSH ключи для доступа GitHub Actions к вашей виртуальной машине:
        
        \begin{lstlisting}[language=bash, numbers=none, frame=single, basicstyle=\ttfamily\footnotesize, columns=fullflexible, keepspaces=true, breaklines=false, commentstyle=\color{gray}\itshape, extendedchars=true, texcl=true, showstringspaces=false]
# Генерируем SSH ключи (на вашей виртуальной машине)
ssh-keygen -t rsa -C "github-actions" -f ~/.ssh/github_actions -N ""

# Добавляем публичный ключ в authorized\_keys
cat ~/.ssh/github_actions.pub >> ~/.ssh/authorized_keys

# Выводим приватный ключ для добавления в GitHub Secrets
cat ~/.ssh/github_actions
        \end{lstlisting}
        
        \item Скопируйте содержимое приватного ключа и добавьте его в GitHub Secrets:
        \begin{itemize}
            \item Перейдите в Settings → Secrets and variables → Actions
            \item Нажмите New repository secret
            \item Name: \texttt{SSH\_PRIVATE\_KEY}
            \item Value: вставьте содержимое приватного ключа целиком (включая \texttt{-----BEGIN} и \texttt{-----END} строки)
            \item Сохраните секрет
        \end{itemize}
    \end{enumerate}
\end{task}

\begin{task}{2}
    Настроить SSH доступ до вашей виртуальной машины через FRP для работы CD workflow.
    
    \begin{enumerate}
        \item Обновите конфигурацию FRP для работы с GitHub Actions:
        
        \begin{lstlisting}[language=bash, numbers=none, frame=single, basicstyle=\ttfamily\footnotesize, columns=fullflexible, keepspaces=true, breaklines=false, commentstyle=\color{gray}\itshape, extendedchars=true, texcl=true, showstringspaces=false]
# Настройка переменных.  Актуальные значения узнайте у преподавателя!
PROXY=course.prafdin.ru
TOKEN=tokentoken
ID=prafdin
SSH_PORT=2200

# Обновляем конфигурацию FRP - убираем webhook, добавляем SSH
# Команда запросит пароль текущего пользователя
sudo tee /etc/frp/frpc.toml > /dev/null <<EOF
serverAddr = "$PROXY"
serverPort = 7000

auth.method = "token"
auth.token = "$TOKEN"

# Проброс для приложения (остается как было)
[[proxies]]
name = "app-$ID"
type = "http"
localPort = 8181
customDomains = ["app.$ID.$PROXY"]

# Новый проброс для SSH доступа GitHub Actions
[[proxies]]
name = "ssh-$ID"
type = "tcp"
localPort = 22
remotePort = $SSH_PORT
EOF

# Перезапустите frpc
sudo systemctl restart frpc

# Проверьте SSH подключение к серверу через новый порт
ssh -p $SSH_PORT $USER@$PROXY
        \end{lstlisting}

    \end{enumerate}
\end{task}

\begin{task}{3}
    Создать CI workflow для проверки кода.
    
    \begin{enumerate}
        \item Создайте файл \texttt{.github/workflows/ci.yml}
        \item Добавьте простые тесты для вашего приложения (если их нет)
        \item Настройте workflow для запуска тестов при push нового коммита и создания pull request
        \item Убедитесь, что workflow запускается и успешно проходит
    \end{enumerate}

    В этом workflow вся работа (сборка, тестирование) должна происходить на GitHub Runner.
    В рамках CI workflow подключения до виртуальной машины не требуется.

    \textbf{Полезная информация:}
    \begin{itemize}
        \item \href{https://github.com/actions/runner-images?tab=readme-ov-file#available-images}{Список предустановленного ПО на GitHub Runners}
        \item Полезные GitHub Actions: 
        \begin{itemize}
            \item \href{https://github.com/actions/checkout}{actions/checkout}
            \item \href{https://github.com/actions/setup-dotnet}{actions/setup-dotnet}
            \item \href{https://github.com/actions/setup-python}{actions/setup-python}
        \end{itemize}
    \end{itemize}
\end{task}

\begin{task}{4}
    Создать CD workflow развертывания приложения.

    \begin{enumerate}
        \item Создайте файл \texttt{.github/workflows/deploy.yml}
        \item Настройте workflow для запуска только после успешного выполнения CI workflow в заданной ветке (например, \texttt{github-actions})
        \item Реализуйте ту же логику развертывания, что была в webhook веб-сервере
        \item Протестируйте развертывание
        \item Убедитесь, что приложение обновляется и доступно по тому же адресу: \texttt{http://app.\$ID.\$PROXY}
    \end{enumerate}

    Этот workflow должен включать в себя сборку и развертывание приложения.
    Сборку необходимо производить на GitHub Runner.
    Для доступа к виртуальной машине воспользуйтесь предварительно добавленным приватным ключом через \href{https://docs.github.com/ru/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets}{GitHub Secrets}

    \textbf{Полезная информация:}
    \begin{itemize}
        \item \href{https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run}{Инструкция по настройке запуска workflow на основании статуса другого workflow}
        \item Полезные GitHub Actions:
        \begin{itemize}
            \item \href{https://github.com/appleboy/ssh-action}{appleboy/ssh-action@v1}
            \item \href{https://github.com/webfactory/ssh-agent}{webfactory/ssh-agent@v0.7.0}
            \item \href{https://github.com/appleboy/scp-action}{appleboy/scp-action@v1}
        \end{itemize}
    \end{itemize}
    
    \textbf{Примечание:}
    \begin{itemize}
        \item Все необходимые зависимости приложения предварительно могут быть установлены вручную на виртуальной машине.
        Список зависимостей должен быть зафиксирован в документации или специальном файле, например, в requirements.txt в случае Python приложения.
        \item Разворачиваемое приложение должно быть доступно по адресу \texttt{http://app.\$ID.\$PROXY} и запущено на порту 8181
    \end{itemize}
\end{task}
